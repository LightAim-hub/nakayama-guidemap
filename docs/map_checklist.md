一度でも名前が出た店を集める。60店中58店は出る。出ないのは次の2件:

  名前をどちら側に置いても隣の印のほうが近くなる。名前は「いちばん近い印のもの」として読まれるので置けない。
- **中山の坂の上** — バス通りの頂上そのものを指す目印なので、名前の枠がどの向きでも道路の塗りに乗る。

どちらも一覧には出るし、印を押せば詳細が開く。

## B. 印が読めるか・押せるか

| # | 見るところ | 合格 | いまの状態 |
|---|---|---|---|
| B1 | 印どうしが重なっていないか | 0組 | 0組（押し分けで解消・元は4組） |
| B2 | 印が道路の塗りに乗っていないか | 0件 | 0件（元は8件） |
| B3 | 印の見た目の大きさ | 14px以上 | 14.0px（N12） |
| B4 | 押せる範囲 | 44×44px以上 | 45px（N43） |
| B5 | 印を押したら その店が開くか | 密集していても開く | **6/6**（実タップ・下記） |
| B6 | 実際の指で押して詳細が開くか | 開く | 実タップで確認済（合成clickでは判定しない） |
| B7 | 押し分けで動かした距離 | 実位置から18m以内・通りは渡らない | 最大 18.0m（1.40〜1.45 px/m のみ。1.80以上では 0.4m） |

**B5 について**: 押せる範囲は 45px、いちばん近い印どうしは 15px しか離れていないので、
「44px の押し範囲どうしを 8px 空ける」は、印を実際の場所から動かさない限り成り立たない。
そこで**押し範囲を分けるのではなく、押した所からいちばん近い印を開く**ようにした。
印そのものを押せば必ずその店が開き、ちょうど2つの印の境目を押した時だけ「どのお店？」が出る。

押した所で何を見るかの順番（この順でないと取り違える）:

1. **印の上（中心から7px以内）→ その印の店**。他店の名前がその印の上に重なっていることが
   あるので、名前より印を先に見る。
2. **印から離れた所で、店名の文字や声のふきだしの上 → その名前の店**。
   ここを「いちばん近い印」で決めていた時は、幅118pxの名前の端を押すと隣の店が開いていた
   （実測12件中6件。「Double Egg5丁目」の名前を押すと おたからや が開いた）。
3. **押せる範囲の中の、何も描いていない所 → いちばん近い印**。2番目との差が10px未満の時だけ選択窓。

実測（縦390×844・実タップ）:

- 印の真ん中を押す（密集した6件）→ **6/6 その店が開く**
- 店名のいちばん遠い端を押す（幅の広い12件）→ **12/12 その名前の店が開く**

## 測り方

```bash
python tools/v2-build/build_mapdata.py     # 生成
python tools/v2-build/gate.py              # 合否の正本 (exit 0 が合格)
```

縮尺を振っての A/B 検査は `tools/v2-build/` の外（スクラッチパッド `audit4.py`）で回している。

**注意点（実際に踏んだ落とし穴）**

- 割合を出す時の分母は **地図の枠（`#viewport`）**。ウィンドウ全体で数えると、見出し帯や下の帯に隠れた印まで数に入る。
- 測る前に **`document.fonts.ready` を待つ**。待たないと同じ画面でも結果が変わる。
- `window.dispatchEvent(new Event('resize'))` を呼ぶと初期表示に戻るので、縮尺を変える検査では使わない。
- 「押せる」は合成 click で判定しない。実マウス・実タップで確かめる。
- `file://` で開くとフォントが CORS で読めず、代替フォントの幅で測ってしまう。
  必ず `python -m http.server` 等で **http 経由**で測る。
- 「名前が出ない理由」は自分で推定しない。本体が `window.__labelPriorityReject` に
  「どの条件で何件落ちたか・誰に邪魔されたか」を残しているので、それを読む。
