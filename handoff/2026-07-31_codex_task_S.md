# Codex 作業指示 S — 自分の声バッジが自分の店名を消してしまう問題を直す（N26）

対象: **`tools/v2-build/template.html`**（`layoutLabels()` と `layoutVoiceBadges()`）
前提: Task R 完了後の作業ツリー。ゲートは N26 の1件を除いて全項目0件。

## Task R の結果と、今回の位置づけ

Task R（声あり11店を先に同時決定するバックトラック探索）は入りましたが、**N26 は変わりませんでした**。

```
python tools/v2-build/gate.py
  【N26】こどもの声の店のラベルが端末を問わず出ている — 違反 1件
        ウエルシア薬局 のこどもの声ラベルが出ていない [360x640]
```

探索の作りは悪くありません。**そもそも ウエルシア薬局 の候補が 0通り**なので、
どんな探索でも置けないのが真因です。以下は Claude Code が実ブラウザで測った内訳です。

## 真因（実測・360×640）

`ウエルシア薬局` の候補336通りが、どこで落ちているか:

| 却下理由 | 360×640 | 390×844 |
|---|---|---|
| 引き出し線の向きが自分の★を向かない | 201 | 190 |
| 自分の★が最近傍でない（N14相当） | 65 | 64 |
| ズームボタン（`.zoomctl`）に当たる | **65** | 0 |
| **自分の「こどもの声」バッジに当たる** | **5** | 8 |
| **置ける** | **0通り** | 74通り |

- ★は画面 (199,487)、表示域は 360×345（y 189〜534）
- `.zoomctl` は画面 (304,430)–(348,526)。★の右に「ウエルシア薬局」(約102px) を置くと
  右端が 307 になり、ズームボタンの左端 304 と 3px 重なる → **右側は全滅**
- 左へ逃げた最後の5通りを、**その店自身の声バッジ**が潰している

`voiceBadgeAngles(preferredLabelSide(s))` は `base = side>0 ? Math.PI : 0` なので、
バッジは**ラベルの反対側**に置く設計になっています。ウエルシア薬局は東側なので
ラベルの既定側は右・バッジは左。ところが固定UIがラベルを左へ追いやるため、
**設計上「絶対にぶつからないはず」の2つが正面衝突**しています。

つまり「こどもの声の店です」と示すバッジが、その店の名前を消しています。

## S-1 自分のバッジは自分のラベルを塞がない

`layoutLabels()` の `overlapsMapSymbol()` は、いま**全部のバッジ**を避けています。
ここを **「自分（同じ店）のバッジは除く」** に変えてください。

- 他店のバッジ・信号アイコンは今までどおり避ける（どの★のバッジか分からなくなるため）
- 自分のバッジだけは、自分のラベルの障害物にしない

そのために `mapKeepOut` を「ただの矩形の配列」から**どの店のものか分かる形**にします。
`layoutVoiceBadges()` の戻り値に店の `idx` を持たせ、信号は `idx` なしにするなど、
やり方は任せます。既存の呼び出し（`template.html:894` 付近）も合わせて直してください。

## S-2 ラベルを決めた後に、バッジを置き直す

S-1 だけだと、バッジがラベルの上に乗ったままになり得ます。バッジが読めなくなるので、
**ラベル確定後にバッジをもう一度置き直します**。

```
1回目 layoutVoiceBadges(...)      仮置き（他店のラベルがこれを避けるために必要）
      layoutLabels(...)           自分のバッジだけ除いて配置を確定
2回目 layoutVoiceBadges(..., 確定したラベル矩形)   バッジを最終決定
```

2回目では、既存の候補探索（角度25通り × 間隔3通り）の合否判定に
**「確定した全ラベルの矩形と重なるものは不可」**を足します。

- 見つからない時は、いまの fallback をそのまま使ってください（バッジが消えるのは不可）
- バッジが自分の★に一意に結びつく条件（`ownDistance + .01 < nearestOther`）は維持

Claude Code の実測では、**4サイズすべてで11店とも置き直せます**（11/11）。
そのうえで こどもの声11店のラベルも同時に置けます（探索12手）:

| 端末 | 自分のバッジを除いた時の ウエルシア薬局 の候補 | 11店同時配置 | バッジ置き直し |
|---|---|---|---|
| 360×640 | 0通り → **5通り** | 置ける | 11/11 |
| 375×667 | 24通り → 31通り | 置ける | 11/11 |
| 390×844 | 74通り → 74通り | 置ける | 11/11 |
| 428×926 | 96通り → 96通り | 置ける | 11/11 |

## S-3 探索に打ち切りを入れる（Task R で入った再帰の安全網）

Task R で入った `placePriority` は**打ち切りの無い再帰**です。いまの条件では12手で終わりますが、
制約が変われば組み合わせ爆発で端末が固まります。地図が固まるのは最悪の壊れ方です。

- 探索の**手数に上限**を設け（目安 20000手）、超えたら既存の貪欲配置へ静かに退避する
- 退避したことが分かるよう、`document.body.dataset` などに痕跡を残す（任意）
- ゲートに描画時間の検査を追加します（Claude Code 側）。既定ズーム↔歩きズームの
  往復で `layoutLabels` が **1回あたり400ms以内**であること
