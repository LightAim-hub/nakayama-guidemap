# BN: 本文の上限を「入らない所だけ」に狭める（文字サイズ対応・3周目）

BM で gate は PASS（N1〜N60・違反0件）になった。**崩れは直っている。**
残る問題は、直し方が広すぎて **文字を大きくした人にほとんど効かなくなった**こと。

いま `--body-font-max:18px` を本文15箇所に当てているので、端末を200%（32px）にしても
本文は 18px（＝既定比 112%）で止まる。これでは「文字を大きくする」意味がほぼ無い。
このマップを一番必要とする人（お年寄り）に効かない直し方になっている。

## 触ってよい / いけない

- 触る: `tools/v2-build/template.html`
- **触らない: `tools/v2-build/gate.py` / `index.html` / `v2.html` / `mapdata.json` / `official_details.json`**

## 事実（BLで直す前の本番を、端末32pxで実測した結果）

| 画面 | 32px で崩れていたか |
|---|---|
| 入口（通り沿いの二列） | **崩れる**（カードが画面幅の半分に固定・横33px はみ出し） |
| header | **崩れる**（44px の箱に105px の中身） |
| お店一覧 390x844 | **崩れない** |
| お店一覧 320x568 | 店名が語の途中で折り返す（N57・5件） |
| 詳細シート 390x844 | **崩れない** |
| 詳細シート 320x568 | 「次へ →」が割れる（N28/N58） |

つまり **上限が要るのは、幅が構造的に足りない所だけ**:
二列のカード（画面幅の半分）と、320px 幅の狭い端末。
**390px 以上の一覧と詳細は、端末の設定にそのまま追従してよい**（実測で崩れない）。

## やること

`--body-font-max` の当て方を、上の事実に合わせて狭める。

1. **二列のカードの店名** — 上限は残す（構造的に入らない）
2. **狭い端末（おおむね 340px 以下）** — 一覧・詳細にも上限を残す
3. **それ以外の一覧・詳細の本文** — **上限を外し、端末の文字設定に追従させる**
   （`--body-font-max` を広い画面で十分大きい値に切り替える等、実現方法は任せる。
   ただし「1箇所で決めて全部に効く」という BM の作りは崩さないこと）

見出し（`--heading-font-max:24px`）はそのままでよい。header は高さが伸びるようになったが、
天井なしにすると地図と一覧の取り分（N23の床）を食うため。

## 合格条件

1. `python tools/v2-build/build_mapdata.py` が通る
2. `python tools/v2-build/gate.py --target index.html` が **PASS（違反0件・N1〜N60）**
3. 390x844・端末32px で、**お店一覧の店名と詳細シートの本文が 18px より大きくなっている**
   （追従していることの実証。実測値を result.txt に書く）
4. 390x844・端末16px の全文字が BM と同値（既定の見た目を変えない）
5. 歩ける店 60/60 / JSエラー 0

`result.txt` に、16px と 32px それぞれの実測表（一覧の店名・住所、詳細の本文、二列の店名、見出し）を貼ること。
