## BD-1 交差点の信号は1つにする

**やること**: 同じ交差点の信号をまとめる。互いに **30m 未満**の信号は1つとして扱い、
中点に1つだけ描く。13点 → 11点になる想定。

- データを手で削らず、`build_mapdata.py` の中で「近すぎる信号を1つにまとめる」処理として書く。
  OSM 由来の生データ (`signals_raw.json`) は残す。まとめる閾値は定数にして根拠をコメントに書く。
- 二列表示側の信号 (`.strip-signal`) も同じデータから描かれるので、そちらも1つになる。

**確認**: `mapdata.json` の `signals` に 30m 未満の対が0組。gate.py が PASS のまま。

## BD-2 店名を道路に被せない・その店がいる側の余白に置く

**ボスの言葉**: 「道の右側の店舗は右側に、左側は左に、余白がある場所に置いて」

**やること**: `layoutLabels()` の配置規則を、次の優先順で作り直す。

1. **側**: 店が通りの東側なら名前は★の右、西側なら★の左。これを最優先で守る。
   （どちら側かは既存の判定を使う。実座標は変えない）
2. **道路に重ねない**: 置いた名前の外接矩形が道路の線と重なる候補は捨てる。
   同じ側で上下に少しずらして、重ならない場所を探す。
3. **余白**: 他の店名・★・信号・固定UIとも重ならない場所を選ぶ。
4. どうしても置けない時だけ名前を出さない（今の非表示の仕組みのまま）。

**確認**: 既定ズームと歩きズームの両方で、
「見えている店名の矩形」と「道路の線」が重なる件数 **0件**。
私が実ブラウザで数える。**目視で「だいたい良い」は不可。**

## BD-4 写真の表示を本番の詳細シートに載せる

`preview.template.html` にある写真表示を `template.html` へ移植する。**作り直さない。**

移植するもの（preview の実装がそのまま動く形になっている）:

- `setPhotoPicture` / `createPhotoPicture`（`<picture>` で webp→jpg フォールバック）
- `buildPhotoGallery`（メイン1枚＋2枚以上ならサムネ・`aria-pressed` で切替・`aria-live` で読み上げ）
- `ensurePhotoLightbox` / `openPhotoLightbox` / `closePhotoLightbox`（拡大表示・Escで閉じる・focus戻し）
- 対応するCSS（`.detail-photo-main` / `.detail-photo-thumbs` / `.photo-lightbox*` 一式）

置く場所は preview と同じく **住所の下・「こどもの声」等のバッジの上**。
写真が無い店では今と1pxも変わらないこと（`s.photos` が無ければ何も足さない）。

注意:
- `img` に `width`/`height` か `aspect-ratio` を必ず持たせる（読み込みで画面が跳ねない・gate N7相当）。
- Esc の閉じる順序は「写真の拡大 → 詳細シート」。今の Esc 処理に割り込ませる。
- 画像は `loading="lazy"` / `decoding="async"`。

## BD-5 拡大したあと、指で地図を動かせるようにする

**今できないこと**: 拡大しても1本指で地図をずらせない。行きたい方向へ移動できない。

**やること**: `#viewport` に1本指ドラッグでの移動を足す。

- 指を置いて動かした分だけ `viewBox` の `x`/`y` を動かす（拡大率に応じて距離換算する）。
- 慣性は不要。指を離したら止まってよい。
- **10px 以上動いたらタップとして扱わない**（既存の `singleTouch.moved` を使う。
  ドラッグで店の詳細が開く事故を起こさない）。
- マウスでも同じように動くこと（PCで見る人・私の検証で必要）。
- 動かせる範囲は地図の外へ延々と行かない程度に留める（全体表示の範囲＋少しの余白）。
- ピンチ中 (`pinchGesture`) は1本指の処理を動かさない。

**確認**: 拡大3回した状態で 100px ドラッグ → `viewBox.x`/`y` が動く。
ドラッグ後に詳細シートが開いていない。
