## 背景（何が分かったか）

### 1. `src` の書き換えでゲートが緩んでいた

Task I で10店の `src` が `gsi_addr` → `approx` に変わっていました。`src` は N7 の
上限を決めるキーなので、書き換えは閾値を緩めるのと同じです。実測すると1店が
その緩みを使っていました:

```
中杜建設  直交 23.8m   gsi_addr なら上限20mで不合格 / approx の25mで合格
```

移動そのものは妥当です（住所点は街区の道路側にあるので、奥へ入れる直交移動は正しい補正）。
そこで**判定の根拠を付け替えました**:

- 直交の上限は「同一住所グループの構成員か」で決める（`MAX_CROSS_PAIRED = 25m`）。`src` では決めない
- `N16` が `src` の書き換えを検出する。基準は `tools/v2-build/src_baseline.json`（公開中の本番 `ece309c` 由来）

**→ `src` を戻しても N7 は0件のままです。**

## K-2 OSM に実体がある店はそれを真座標に使う

1. `tools/v2-build/osm_pois.json` を正本に追加（**私がコミット済み**・ネットワーク取得は不要）
2. 店名の正規化突合を builder に入れる:
   - 空白・記号（`・（）()【】「」,、.。/-ー`）を除去、全角→半角、`株式会社`/`有限会社`/`合同会社` を除去、小文字化
   - 完全一致を優先。無ければ**どちらかがどちらかを含む** 4文字以上の部分一致
   - **複数候補が出たら採用しない**（`ヨークベニマル 仙台中山店` は OSM の `branch=荒巻店` と
     誤照合し1815.9m ずれます。`Double Egg4丁目` は 5丁目のノードに当たります）
   - 採用した店は `src` を `osm:exact` にし、`src_baseline.json` も更新する
     （更新理由をコメントに書く。N16 はこのファイルを基準に判定します）
3. 上表の3件が `osm:exact` になり、真座標が OSM 座標になること
4. その後は**既存の I-1（建物寄せ）→ N8（分離）の順で解き直す**。生の OSM 点をそのまま
   表示座標にしないこと

**この3件以外を勝手に差し替えないこと。** 突合で新たに採用したい店が出たら、
店名・OSM id・タグ・距離・東西が保持されるかを報告して、私の確認を待ってください。
