## ボスの指摘と、測って分かった真因

> 道路の横幅であったり交差点の位置であったりっていうのはその店舗の縮尺に合わせないと
> 実際の位置関係にならないんじゃないか。合わせてないから道路の上に星が出てきてしまう

**メカニズムの見立ては正しい。ただし道路はもう縮尺の内にいる。**

| 要素 | 実測 | 縮尺 |
|---|---|---|
| 道路の幅 | 13m / OSM実幅12〜14m（`tertiary` `lanes=2`） | **内**（`189986e`で34m→13mに修正済） |
| 道路の長さ | 1718.8m / 実1719.0m（差0.2m） | **内** |
| 道路の中心線の形 | 簡略化 中央値1.9m・最大5.2m | **内** |
| 信号の座標 | バス通り中心線から ±0.0〜0.1m | **内** |
| **★の絵** | **14〜23m / 実店舗の間口 約10m** | **外（約2倍）** |
| **ラベル1枚** | **幅91m / 通りの幅13m** | **外（7倍）** |
| タップ半径 `padr` | 44m | 外 |

→ **いま縮尺の外にいるのは ★ と ラベル。** これが「道路の上に星」の直接原因。

もう1つ、縮尺とは無関係の原因:
**住所ジオコーディング（`gsi_addr`）は街区の「道路に面した接点」に点を置く。** 道路中心線までの
距離の中央値は `gsi_addr` **9.7m** に対し `osm:exact` 19.2m。これで13店が実際に道路の帯の内側にいる。

## I-1 店を建物の中に入れる（N1=0 / N2=0）

`tools/v2-build/buildings_raw.json`（OSM建物輪郭 11,795件・`out geom`・canvas内5,508件）を正本にする。

1. builder で建物ポリゴンを既存 `project()` で canvas 座標に変換
2. 各店:
   - 建物の内側にいる → **動かさない**
   - 外にいる → 最近傍の建物の内側へ寄せる。寄せ先は重心でなく**元の点から最短で入る内部点**（境界から2m以上内側）
3. 移動で壊してはいけない制約（この順に優先）:
   - どの道路の帯の内側にも入らない（中心線からの距離 ≥ 塗り幅/2 + 2m）
   - **バス通りの東西の側**が変わらない（N5 は現在0件・絶対に維持）
   - **南北の並び順**が変わらない（真座標の順序）
   - 同一住所5組の上下と14m分離を維持
4. 建物内判定の除外（建物が存在しない敷地・動かさない。公園は自分のポリゴン内にいることを確認）:
   `たきみち公園` / `なかやまとびのこ公園` / `中山山の神公園` / `中山小学校` / `中山中学校` /

5. `商店街モニュメント` は道路の帯の外へ出すだけでよい（現在 mid道路から1.7m）

## I-2 ★とラベルを縮尺の内に戻す（N3=0 / N4=0）★このタスクの本体

**★が19.3m固定である限り、店を建物に入れても絵が道路を覆って台無しになる。** I-1 と不可分。

### I-2a ★を画面px固定にする

- `applyZoom` で `use.star` の scale を毎回再計算: `targetPx / (pxPerMeter * 20)`（20 = `#starShape` の基準幅）
- 目標: 通常 **11px** / アンカー店（こどもの声あり・公園等） **14px**
- **下限 6px**（これ未満は見えない）／**歩きズーム（2px/m）での地図空間サイズは 10m 以下**
- 効果: 拡大すると★の地図空間の見かけが縮み、道路の横に正確に収まる
- **Task H で入れた「8m以内の微小変位（22店）」は撤去する。** I-1 の建物内配置を壊すため。
  ★が小さくなれば密集対策としての変位はもう不要

### I-2b ラベルを★の隣に置く（N4 の37件を0にする）

現行は「同じ高さの店を束ねて左右の列に整列」方式で、ラベルが自分の★から最大93m離れ、
**37店でラベルが自分の★より他人の★に近い**。歩きながら照合できない。

- ラベルの理想位置 = **自分の★のすぐ隣**（★の縁から画面4〜6px）
- ハード制約: **どのラベルも、自分の★までの距離が、他のどの★までの距離より短い**
- 入りきらないラベルは**非表示にしてよい**（ズームで出す）。優先度 = こどもの声あり ＞ 公式URLあり ＞ その他
- **★は60件すべて必ず表示**（サイズを縮めて消すのは禁止・下限6px）
- 引き出し線は「ラベルが★から離れたときだけ」。**引き出し線同士が交差しない**こと
- フォントも画面px固定: 通常 11〜12px / アンカー店 14〜15px（現行 `FS=16.5` の地図単位固定は
  デフォルト実表示7.4px・拡大で41pxになるため廃止）

## I-3 信号を「使える目印」にする（N6=0）— 道路は増やさない

**信号の座標は正しい**（バス通り中心線から±0.0〜0.1m）。問題は「交差する道が描かれていないので
交差点が存在しない」こと。13基のうち7基が交点から20m超（最大363.6m）。

実測した最小の直し方（**533本に増やす必要はない**）:

1. **既存62本の切れ端をつなぐ** — 62本のうち31本が2点の断片で、交差するはずの位置に届いていない。
   例: 信号(570.0, 805.5) は20m以内に描画済みの道が2本あるのに、その2本が互いに交わっていないため
   交点から46m浮いている。同clsで端点距離<2mのチェーンをマージし、交差すべき相手に届くまで
   元way形状に沿って延長する（OSM上の実際の行き止まりはそのまま）
2. **足りない交差道だけを追加** — 全信号を交差点にするために必要なOSM道は**実測16本**。
   `osm_raw2.json` の `geometry` 付き道路way（2,309本）から、各信号の20m以内を通り
   かつ未描画のものだけを取り込む
3. **手置きの信号2基を削除** — OSMに対応する `highway=traffic_signals` が無い:
   (403.6, 272.2) / (490.9, 482.5)（後者は交点から131.7m）
4. **欠落の2基を追加** — (580.9, 1273.1) / (279.4, 865.2)
5. 以後、信号は `signals_raw.json` の `highway=traffic_signals` の canvas内全数のみを使う

**合格**: 全信号が交差点から20m以内。道路本数の増加は **+16本以内**（62 → 78本以下）。

## 進め方 — gate.py が緑になるまで自分で回す

**1周で終わらせない。** `gate.py` は1本走らせれば60店ぶん判定して、1件でも違反なら exit 1 を返す。

```
繰り返し:
  1. python tools/v2-build/build_mapdata.py        (--preview なし)
  2. python tools/v2-build/gate.py --json .tmp-runtime/gate.json
  3. exit 0 なら終了。違反があれば、違反リストを見て直して 1 へ戻る
```

**exit 0 になるまで報告しないでください。** 途中の数値だけを出して終わるのは不可。
どうしても達成できない項目が残る場合は、**何がどの数値で止まったか・なぜ物理的に不可能か**を
実測値で示してください。

  座標は毎回 lat/lng と建物ポリゴンから導出すること

## HTTPサーバを立てる場合（前回のハング再発防止）

前回 Task H は固定ポート8765を別プロセスが掴んでいてコマンドが返らず**2時間19分ハング**した。

1. ポートは **`socket.bind(('127.0.0.1', 0))` で空きを動的取得**
2. 起動はバックグラウンド。readiness は HTTP GET のタイムアウト付きポーリング
3. 起動待ちは**最大30秒でタイムアウト**。失敗したらサーバ無しの検査に切り替える
4. 使い終わったら必ず停止する

`gate.py` は `--url` を省略すればこの手順で自前にサーバを立てます。実ブラウザが起動できない場合
（前回は `WinError 5 / spawn EPERM`）は `--no-browser` で走りますが、その場合 N3/N4 は判定されず
**合格になりません**。その旨を報告に明記してください。
